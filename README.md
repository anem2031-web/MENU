# Al Malqa Digital Menu

مشروع المنيو الرقمي الخاص بكوفي الملقا. واجهة العميل عامة بدون تسجيل دخول، ولوحة المالك محمية بجلسة آمنة.

## الباركود الثابت وأرشيف الوجهات

قسم «QR العميل» يحفظ هوية باركود واحدة في قاعدة البيانات. الرابط المشفّر `/q/<token>` لا يُعدّل ولا يُحذف عبر الواجهة؛ تتغير الوجهة فقط بعد تأكيد، مع سجل مراجعات. إعادة التنزيل أو تغيير إعدادات المنيو لا يولّد هوية جديدة. الباركود المباشر القديم، بما فيه المحفوظ سابقًا في localStorage، لا يصبح ديناميكيًا بأثر رجعي.

قبل نشر الميزة، طبّق التحديث الإضافي للجداول على قاعدة البيانات المقصودة:

```powershell
pnpm --filter @almalqa/db qr:migrate
pnpm build
```

الأمر يطبّق فقط `0006_customer_qr_archive.sql`، ولا يولّد باركودًا أو يمس بيانات المنيو. لا تكتفِ بتشغيل Drizzle migrate: بعض التحديثات اليدوية السابقة غير مسجلة في journal. راجع نسخة احتياطية وصلاحيات الاتصال قبل التشغيل. هذا التحديث لم يُطبّق تلقائيًا على قاعدة الإنتاج أثناء التطوير.

اضبط `QR_PUBLIC_ORIGIN=https://YOUR-OWNED-DOMAIN` قبل الإنشاء الأول، بعد ربط النطاق بخدمة HTTPS تخدم `/q/*`. إن تُرك فارغًا، تُستخدم واجهة الموقع الحالية بعد تأكيد المستخدم. تغيير المتغير بعد الإنشاء لا يغيّر الرابط المؤرشف أو المطبوع. حافظ على النطاق ومسار التحويل عند نقل الاستضافة.

التحويل الحالي يستخدم HTTP 302 مع `Cache-Control: no-store` ويعتمد على خادمنا وقاعدة البيانات. لم يتم إعداد خدمة تحويل مستقلة على Cloudflare أو DNS؛ يتطلب ذلك نطاقًا وحسابًا يملكهما المستخدم وتكاملًا منفصلًا. لا تطبع أو تحفر باركود localhost أو عنوان استضافة مؤقت. لا يمكن استعادة التحكم بباركود الشركة السابقة بهذه الميزة.

نزّل SVG ونسخة الأرشيف JSON واحفظهما خارج الموقع، مع نسخ قاعدة البيانات. نسخة JSON للتوثيق والنقل اليدوي؛ ليست نظام استعادة تلقائيًا. لا توجد شاشة لإعادة إصدار أو حذف الهوية الثابتة بالخطأ.

اختبارات الخادم: `pnpm --filter @almalqa/server test`. للاختبار البصري المعزول استخدم `apps/server/tests/fixtures/qr-server.ts` (ذاكرة فقط، منفذ localhost:3199) و`apps/web/tests/fixtures/qr-archive.html` مع توجيه `/trpc` و`/q` و`/test-menu` إلى خادم الاختبار. لا تفتح fixture على اتصال الإنتاج.

## التشغيل على Windows PowerShell
من جذر المشروع:

```powershell
pnpm install
pnpm typecheck
pnpm dev
```

الواجهة: `http://localhost:5173`  
الخادم: `http://localhost:3001`  
لوحة المالك: `http://localhost:5173/admin`

## المرحلة 7 — الصور وIDrive e2
النسخة الحالية تضيف:
- `@aws-sdk/client-s3` للربط مع IDrive e2/S3.
- Multer لاستقبال ملف واحد في الرفع.
- Sharp لتصغير وضغط الصور وتحويلها إلى WebP.
- حد 8MB وأنواع مسموحة JPG/PNG/WebP/AVIF.
- رفع شعار الكوفي وصور الأقسام وصور الأصناف مباشرة من لوحة المالك.
- حفظ المفتاح والرابط في TiDB: الشعار في `cafe_settings`، وصور الأقسام والأصناف في حقول `image_key/image_url`.

تحديث v2.6 يضيف حقلي `image_key/image_url` إلى جدول `categories`، لذلك يلزم توليد Migration جديدة ثم تطبيقها قبل اختبار صور الأقسام.

بعد الاستبدال شغّل `pnpm install` لأن هذه المرحلة تضيف حزمًا جديدة، ثم ضع بيانات IDrive e2 في `.env` حسب:

```text
docs/IDRIVE_E2_SETUP.md
```

## التخزين والأسرار
- قاعدة البيانات: TiDB / `MENU`.
- الصور: IDrive e2 عبر S3-compatible API.
- لا تضع `S3_SECRET_ACCESS_KEY` أو كلمة مرور TiDB داخل Git أو ملفات ZIP التي تشاركها.
- `.env` مستبعد من Git أصلًا.
